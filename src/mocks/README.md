# Mock API

A fake backend built with [MSW](https://mswjs.io). It answers the app's real HTTP calls in the browser, so you can build and demo the UI before the backend exists.

```bash
npm run dev:mock
```

It sets `NEXT_PUBLIC_API_MOCKING=enabled`. With plain `npm run dev`, mocks are off and requests go to `NEXT_PUBLIC_API_URL`.

| Account              | Password   | Can                                |
| -------------------- | ---------- | ---------------------------------- |
| `admin@example.com`  | `password` | read and write users               |
| `viewer@example.com` | `password` | read only (no "New user" / delete) |

A small "Mock API" badge in the corner shows when mocks are on.

---

## How it works

- `public/mockServiceWorker.js` is MSW's service worker (generated by `npx msw init public`; don't edit it).
- `ApiMockingGate` in `_app` starts the worker before the app renders, so even the first request is mocked. With mocks off it renders the app straight away and MSW is never downloaded.
- Handlers match full URLs built from `NEXT_PUBLIC_API_URL` (`apiUrl('/users')`), so the app code doesn't change at all between mock and real backend.
- Data lives in memory in `db.ts` and resets on page reload.
- Access tokens expire after 5 minutes, so the refresh-token flow runs while you click around.
- Searching users for `!error` returns a 500, to see error states.

```txt
src/mocks/
├── db.ts                  seed data, demo accounts
├── session.ts             fake tokens, current user, permission check, 401/403 helpers
├── handlers/
│   ├── auth.handlers.ts   login, me, refresh, logout
│   ├── users.handlers.ts  list (search + pagination), create, delete
│   └── index.ts           all handlers
├── browser.ts             setupWorker
├── MockServiceWorker.tsx  starts the worker (client only)
├── ApiMockingGate.tsx     waits for the worker, shows the banner
└── MockBanner/
```

## Add a mock endpoint

1. Write the real API function in `src/apis/<domain>/` first.
2. Add `src/mocks/handlers/<domain>.handlers.ts`:

```ts
import { delay, http, HttpResponse } from 'msw';
import { apiUrl, getRequestUser, unauthorized } from '../session';

export const productsHandlers = [
  http.get(apiUrl('/products'), async ({ request }) => {
    await delay();
    if (!getRequestUser(request)) return unauthorized();
    return HttpResponse.json({ data: [{ id: 'p1', name: 'Coffee' }], total: 1 });
  }),
];
```

3. Add it to the list in `handlers/index.ts`.

Mirror the real backend's response shapes and error bodies (status codes, `message`, `errors`), so the UI handles them the same way in both modes.

---

## Rules for AI agents

- Mocks only answer requests; never import from `src/mocks` in feature code (only `_app` does).
- Every new endpoint used in the UI gets a mock handler, so `npm run dev:mock` keeps working.
- Keep mock data realistic and small; put it in `db.ts`.
- Unhandled requests pass through to the network, so a missing handler shows up as a network error.
